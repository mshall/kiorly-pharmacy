# Growth: provider links (GRW-P4-B1)

Status: as-built on `main`, 24 Nov 2026 (Wave W5 lane A4). Nothing is pushed or deployed. Every default marked PROPOSED_DEFAULT is a founder decision pending. Kiorex side (decision on orders, the `acquisition` block) is P4-B2 in W7; the staff-app tab and the polished web page set are P4-B3 in W9.

## Promise
A pharmacy can hand its own customers to its Kiorex pharmacy page through a link or a printed QR code and see how many came and how many orders followed. Nothing about a person, a basket or money is stored or shown here.

## What exists
- Code: `apps/api/src/modules/growth/`. Copy, never import across products: `link-code.ts`, `qr-svg.ts`, `link-tags.ts`, `link-touch.ts`, `poster-html.ts` are copies of the Clinic files (`clinics-management/apps/api/src/growth/provider-links/`); `fixtures/link-code-vectors.json` (generated by the Clinic code) and `fixtures/qr-golden.svg` (Clinic golden) prove the parity in `growth.node.test.ts`.
- Schema (migration `20261203110000_growth_provider_links`, additive): `ProviderReferralLink` (`orgId`, `branchRef`, `ownerScope` ORG|BRANCH|DESK, `channelKind`, `code` unique, `label`, `status` ACTIVE|PAUSED|REVOKED, `tags`, audit columns) and `ProviderReferralLinkDaily(linkId, date, visits, orders, completed)`. The database enforces: code is 8 Crockford characters (no I L O U), BRANCH and DESK need a `branchRef` (branch id) and ORG has none, label 2 to 80 characters, `revokedAt` is set exactly when status is REVOKED, counters are not negative. There is no doctor scope. A DESK link's `label` names the counter.
- Link lifecycle (web `/growth/links`, app `/mobile/growth/links`): create, rename, retag, pause, resume, revoke (permanent, web only). Codes are generated with 8 random bytes masked to 5 bits (uniform), retried on collision. A plan limit caps ACTIVE plus PAUSED links (LITE 3, PRO 25, CHAIN 100, ENTERPRISE 500; PROPOSED_DEFAULT, same as the Clinic).
- Roles (PROPOSED_DEFAULT): manage = OWNER, BRANCH_MANAGER; read (view, QR, print the counter card) = PHARMACIST, CASHIER, ASSISTANT, CHAIN_OPS; no access = none (every staff role has at least read). A branch-scoped user (`StaffUser.branchId` set) sees org-wide links and links of their own branch and can change only links of their own branch; org-wide links are head office only. Another organisation's link id is a 404 (no existence leak).
- Kiorex connection: every Growth route (web and app) answers 403 `KIOREX_NOT_CONNECTED` unless the `Tenant.settings.kiorexConnect.status` is APPROVED, or a legacy connection (no recorded state, an active `IntegrationClient`, mode not STANDALONE). The same reading as the Connect to Kiorex front door, without the Kiorex pull.
- Registry events: creating a link queues `ReferralLinkCreated`, revoking queues `ReferralLinkRevoked` through the existing transactional outbox (validated against `@kiorex/contracts` 1.12.0 before it is stored), with `product: "PHARMACY"`, `orgRef` = Tenant id and `clinicRef` = the branch id (the contract field name is `clinicRef`). Creation is flag-gated and needs a connected organisation; **revocation is never flag-gated**. Events carry codes and ids only. Kiorex ingest of them for this product is P4-B2; until then Kiorex acknowledges unknown event shapes, so they are safe to ignore.
- Signed lookup for Kiorex: `GET /marketplace/v1/referral-links/{code}` and the feed `GET /marketplace/v1/referral-links?updatedSince=&limit=&cursor=` (copy of the Clinic 1.11.0 contract, `product` added), authenticated with `MarketplaceHmacGuard`. The client key binds ONE organisation, so a Kiorex client can read only that organisation's links (another organisation's code is `404 REFERRAL_LINK_NOT_FOUND`). A revoke is visible immediately.
- Public resolver: `GET /api/v1/public/links/q/{code}` (no auth, no cookies). Never redirects to a caller-supplied URL: the destination is `KIOREX_PATIENT_WEB_URL` + `/pharmacy` with `lt` (signed touch, 72 h, `{o: org, c: code, t, v:1}` HMAC with the `kx-lt1` prefix, byte-identical to the Clinic token) and the link's UTM tags, and `assertAllowedRedirect` re-checks https (http only on localhost), no userinfo and a configured host before every 302. A malformed code is 404. A paused, revoked or not-connected link still opens the plain Kiorex page (a printed QR must not break) without `lt` and without counting. `Accept: application/json` returns `{target, status}`. Rate limit 300 per minute per code (Postgres, keyed by code, never by visitor).
- Click counts: one atomic upsert per non-bot visit into the UTC-day row. No cookie, no IP, no user agent, no fingerprint is stored (the table has only counters; a test asserts the column list). Bots, link previews and prefetches are not counted (honest limit: a bot that looks like a browser is).
- QR and cards: local `qrcode`, error correction M, 4-module quiet zone (SVG and PNG). Printable A4 and A5 poster and counter card in Arabic (RTL) and English; PDF is the browser's Save as PDF (no server PDF engine).
- Performance (`GET /growth/performance`, counts only): visits, orders and completed through your links versus orders that came through the Kiorex marketplace (RECEIVED to DISPENSED, REJECTED, CANCELLED, EXPIRED (`KiorexOrder`)). Until the Kiorex acquisition block arrives (P4-B2) the link `orders` and `completed` counters are 0 and every Kiorex order is shown as marketplace (`acquisitionPending: true`). There is no money, fee or customer field in any response (tests walk the keys). Statement: "No commission is configured."
- Recommendations (`GET /growth/recommendations`, closed catalogue of five rules, ids only, wording in the web and app strings in AR and EN): `CREATE_FIRST_LINK`, `PRINT_COUNTER_CARD`, `BRANCH_NOT_LISTED`, `LINKS_UNUSED`, `HIGH_REJECTION`. A branch that is not opted in to Kiorex orders (`BranchMarketplaceSetting.optedIn`) triggers `BRANCH_NOT_LISTED`. They use counts only and never what a person ordered or was tested for.
- Staff app API (`/mobile/growth`, `/mobile/growth/links` GET and POST, `PATCH /mobile/growth/links/:id` pause and resume only, `GET /mobile/growth/qr?linkId=`): the plan gate `mobile_staff_app` answers first (403 `FEATURE_DISABLED`), then role and connection. One call returns the whole tab (links with 30-day counts, performance, up to five recommendations, profile URL, statement placeholder, `can`, plan usage). The bootstrap module key `pharmacy.growth` and the app tab are P4-B3 (W9); nothing in `mobile-plan` or `mobile-modules` was changed.
- Web: `/growth` ("Growth & links", Arabic default, EN, RTL, light and dark): summary tiles, links table (QR modal, copy, print AR or EN card, pause, resume, revoke with confirmation), create form, suggestions, statement placeholder, not-connected state with the Connect to Kiorex button. Strings in `apps/web/src/features/growth/growth-strings-data.ts` (merged at runtime, shared locale files only got `nav.growth`).

## Flag
`growth.provider_links` is in `FLAG_DEFINITIONS` (class Module, depends on `pharmacy.module`). OFF: 403 `FEATURE_DISABLED {key, scope}` on create, QR and print; existing links keep resolving and counting, data is never hidden and a revoke still reaches Kiorex. Ships ON (ADR-023). Not a safety control.

## Kiorex acquisition block (GRW-P4-B2, wave 7, 25 Nov 2026)

Kiorex decides every Pharmacy order or booking it takes (origin PROVIDER_LED, MARKETPLACE or UNATTRIBUTED, never a charge: the commission link of products is inert) and may send the result as the optional `acquisition` block of contracts 1.12.0 (`ProductAcquisitionBlock`: origin, decisionId, policyVersion, reason, evidenceHash, optional `linkCode` and `product`). This service stores it and credits its own links; it changes nothing else.

- **Schema** (migration `20270107110000_growth_acquisition_fact`, additive, nullable): `KiorexOrder.acquisitionOrigin` (CHECK: the three origins), `acquisitionDecisionRef`, `acquisitionReason`, `acquisitionLinkId` (set only when the cited code is a link of THIS organisation), `acquisitionOrderCountedAt`, `acquisitionCompletedCountedAt`.
- **Code**: `modules/growth/acquisition-fact.ts` (copy of the shared convention, no cross-product import): `parseAcquisitionBlock` is total: a malformed block, a block for the other product or an absent block is ignored, never a 400; `creditLinkOnce` claims the order row with a conditional update and increments `ProviderReferralLinkDaily.orders` when the order is stored and `.completed` on dispense (DispenseCompleted hook), once each per order.
- **Rules**: only PROVIDER_LED with a code of this organisation counts; another organisation's code, a MARKETPLACE or UNATTRIBUTED origin and a Clinic client's block count nothing (Lab: only a Kiorex booking client can carry the block); no order line, test name or person is read from the block.
- **Tests**: `test/acquisition-fact.e2e.test.ts` (3: stored and counted once with replay, ignored cases, foreign organisation and constraint) and the workspace suite `e2e/test/53-growth-product-ingest.e2e.ts` on the real stack.
- **Gaps**: the staff-app tab (P4-B3) is not built; `growth-metrics.ts` still labels `acquisitionPending` when no link order exists yet.


## Commission rate (COM-2, 25 Nov 2026)

Kiorex sets the commission rate (default per organisation type, own rate per organisation, maker-checker, append-only, effective-dated) and reports the pharmacy's view over the signed machine API: `POST /marketplace/v1/commission-rates` (`CommissionRateView`, contracts 1.13.0; idempotent, newest `version` wins; the signed client key addresses the organisation, `orgRef` is Kiorex's own reference). Stored in `KiorexCommissionRateView`.

- Read: `GET /api/v1/growth/commission-rate` for owners, branch managers and chain operations (others 403 and the page says so). It returns the effective rate now, the default, the own rate with its reason, the next change and the history; the effective rate is computed at read time from the history.
- Web: Growth > **Commission statement** card (en + ar, RTL; 320 / 640x450 / 1440 / 2560). It replaces the old "No commission is configured" placeholder. Nothing reported = **"Rate not set"** and no commission is charged.
- `GET /growth/performance` keeps `statement.configured` (true once a rate is in force); counts only, no money, as before.
- Tests: `test/commission-rate.e2e.test.ts`, `src/modules/growth/commission-rate-view.node.test.ts`, `e2e/growth.spec.ts` (COM-2 cases).

## Commission policy, disclosure and settlement statement (COM-3, 26 Nov 2026; read only)

Founder direction (business policy, **not legal clearance**: counsel has not signed off and real money stays blocked). Kiorex and the pharmacy see the same figures. In Egypt Kiorex pays providers by **bank transfer only** (CBE rules) and never holds or pays cash; a commission on a cash payment is accrued and netted in the next settlement. No wording and no number is shipped here.

- Rate view (`POST /marketplace/v1/commission-rates`) is read tolerantly: the new spec fields (`currency`, `rounding`, `minCollectMinor`, `graceDays`, `retryDays`, `invoiceDueDays`, `reminderDays`, `disputeWindowDays`, `savedMethodChargeAllowed`), `disclosure` and `counsel` are optional and unknown fields are ignored. Stored: the disclosure texts, the counsel **status only** (never reviewer, document or conditions, even if sent) and Kiorex's own `orgRef` (it addresses the statement). `GET /growth/commission-rate` adds `disclosure` (null unless wording is set in EN and/or AR), `counsel: {status}` and `params`.
- Settlement statement: `GET /growth/commission-statement?period=YYYY-MM` and `/commission-statement/:period/export.csv` (audited). Roles as for the rate: owner, branch manager, chain operations. With `KIOREX_MODE=real` it is fetched from `GET {kiorexBaseUrl}/api/v1/partner/commissions/settlement-statement?from&to` (and `/export`; the platform partner route of LG-COM-19, which answers the organisation of the signing key, no organisation in the path) with the partner request HMAC (`signKiorlyRequest`, the integration client's key and webhook secret, `X-Kiorly-Org-Ref`); in mock mode nothing is invented (503 `STATEMENT_NOT_CONNECTED`), a failing Kiorex is 503 `STATEMENT_UNAVAILABLE`. Fees are netted at order release, so the statement carries a fees deduction for pharmacies. **Done (26 Nov 2026, local, not deployed):** the product calls the signed partner route, not the ops route (launch row LG-COM-19).
- Web (Growth > Commission statement card): tabs Rate and Settlement statement; counsel status chip, disclosure blocks only when set (the other language, marked with its own `lang` and `dir`, when only one is written), collection parameters, statement cards, reconciliation chip (matched, unmatched, disputed), payouts with bank reference, CSV. en + ar, RTL, 320 to 2560 px.
- Tests: `com3-commission.node.test.ts`, `test/commission-statement.e2e.test.ts` (private database, in-process signed fake Kiorex), Playwright `e2e/growth-com3.spec.ts` with `playwright.com3.config.ts` (private stack and database, fake Kiorex on 127.0.0.1:5753).
