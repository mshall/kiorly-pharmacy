# Connect to Kiorex (Kiorly Pharmacy), ADR-040

Kiorly Pharmacy works fully on its own. **Connect to Kiorex** (`/kiorex-connect`) guides an organisation that started standalone through joining the marketplace later.

- **Checklist.** `GET /api/v1/kiorex-connect` returns the steps computed from real state, each `done | action_needed | waiting_kiorex | blocked`, with a deep link to fix it. Subscription, branch opt-in (edited in the wizard because the normal Kiorex orders settings are 403 while standalone), priced in-stock non-controlled catalogue, hours and map pin, licence number per branch and an uploaded licence document, payout LABEL placeholder (account-number-like input is refused; no bank data is stored), terms.
- **Request.** `POST /api/v1/kiorex-connect/request` issues a fresh HMAC client and webhook secret, switches the tenant to INTEGRATED, and sends the signed request. Kiorex runs a signed handshake against `/marketplace/v1/catalogue`.
- **Secrets.** Stored sealed in `IntegrationClient`; returned only in the rotation response (`credentials.shownOnce`); never logged or audited.
- **Enrolment code (contracts 1.9.0).** The "Request to go live" step asks for the one-time enrolment code Kiorex ops create for this organisation (Partner onboarding > Enrolment codes). The first request is signed with it; Kiorex answers with an intake key (shown once) which the product keeps sealed and signs every later request with (re-submit, credential rotation). Signing uses `@kiorex/contracts` 1.9.0 (`signIntakeRequest`, `deriveIntakeSigningKey`, `newIntakeNonce`), not a local copy. The code is held in the form only and is never stored. Wrong, used, expired or revoked codes all answer the same way (`ENROLMENT_CODE_REJECTED`). The old shared-webhook-secret signing is gone. Protocol: INTEGRATION.md in the workspace root and `kiorex-contracts` 1.9.0.
- **Status.** The product polls Kiorex with a status token it derives itself (HMAC of the organisation id); nothing is stored. Rejection returns the organisation to standalone.
- **After Go live.** The page offers to make Kiorex Passport the default sign-in (`defaultSignInMethod`) and to invite staff to link their phone.
- **Tests.** ``modules/marketplace/kiorex-connect.node.test.ts`, `web/src/pages/kiorex-connect.node.test.ts``; end to end: `e2e/test/22-standalone-connect.e2e.ts` in the workspace repo.
- **Not done / needs a human.** Counsel-approved terms and fee wording, real notification providers, real launch-gate evidence, the production hand-over channel for enrolment codes.

## Front door: the state-aware Kiorex tab (ADR-040 amendment)

The nav item **Connect to Kiorex** (owner, `settings.write`) opens a front door that picks one of five states from real state (`GET /api/v1/kiorex-connect/front-door`): NOT_CONNECTED (landing and Talk to us), IN_PROGRESS (progress and next step; the full checklist is at `/kiorex-connect/steps`), WAITING (what happens next), LIVE (dashboard) and ATTENTION (paused, changes requested, rejected: decision banner plus what is missing). Live shows Kiorex orders this month (received, dispensed, declined, dispensed value), recent orders without customer names, branches with pause/resume (branch opt-out and back in). Flags live in `Tenant.settings.kiorexFrontDoor`. Fees charged and rating are not available in the pharmacy product, so they are not shown.
- **Wording.** All marketing text is the `kiorexMarketing` namespace (the `kiorexMarketing` block of `apps/web/src/locales/en.json` and `ar.json`). **NEEDS_HUMAN: founder and counsel approve it before launch.** It states no price and no patient number; the fee sentence is built from the published fee schedule when there is one, otherwise it says the fees are confirmed by the Kiorex team.
- **Talk to us.** Inline form (no pop-up): name, role, phone and/or e-mail, preferred time, optional note, consent to be contacted. Sent signed to Kiorex (`POST /partners/v1/leads`, secret `KIOREX_LEAD_SIGNING_SECRET`, dev default outside production only; production value in Secrets Manager `/kiorly-pharmacy/<env>/kiorex-lead-signing`, written by kiorex-platform `scripts/setup-partner-lead-secret.sh <env>`, wired by OpenTofu `lead_signing_secret` / `lead_signing_secret_inject`; `/health/ready` shows `leadSigning` configured or not, never the value); it becomes a lead in Kiorex ops > Partner leads. Viewing the tab while standalone and pressing Start connecting send one PHI-free funnel marker each (organisation id and product only).
- **Home card.** One dismissible card on the home dashboard for standalone organisations; dismissal is stored per user in the browser and the card returns only through "Show the Kiorex card again" on the tab.
- **Tests.** Unit: `kiorex-front-door.node.test.ts` (state mapping, form validation, signing) and the locale parity tests; Playwright `e2e/kiorex-tab.spec.ts` with `playwright.kiorex-tab.config.ts` (every state, widths 360 to 2560, Arabic RTL, dark, axe, home card); real stack: `e2e/test/24-kiorex-front-door.e2e.ts` in the workspace repo.
- **Not done.** Fees charged and rating on the live dashboard; the home-card dismissal is per browser.
